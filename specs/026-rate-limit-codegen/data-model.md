# Phase 1 Data Model: API Rate Limiting & Generated Frontend Types

None of the entities below are new PostgreSQL tables (see research.md Decision 4 — thresholds are env-var config, not DB-driven, so no migration is introduced by this feature). They are either transient Redis state or code-level/build-time artifacts.

## Rate Limit Policy

A named rule protecting one capability. Not persisted as a row anywhere — expressed as a small static registry in code (one entry per protected capability), each backed by a pair of env vars (research.md Decision 4).

| Field | Type | Notes |
|---|---|---|
| `name` | string | Stable identifier, also used as the Redis key prefix (e.g. `guest_token`, `auth_attempt`, `chat_burst`, `search`). |
| `key_dimension` | enum: `origin` \| `identity` | Which extractor produces the Redis key suffix — network origin (research.md Decision 2, unauthenticated endpoints) or resolved user/guest identity (authenticated endpoints). |
| `max_requests` | int | Allowed request count per window; sourced from its own env var, with a default. |
| `window_seconds` | int | Rolling/fixed window length in seconds; sourced from its own env var, with a default. |

Instances (fixed set for this feature, matching spec.md's Functional Requirements):

| Policy | Protects | `key_dimension` |
|---|---|---|
| `guest_token` | `POST /auth/guest` (FR-001) | `origin` |
| `auth_attempt` | `POST /auth/verify`, `POST /auth/register`, `POST /auth/google/authorize`, `POST /auth/refresh`, `POST /auth/guest/refresh` (FR-002) | `origin` |
| `chat_burst` | `POST /chat/completions` (FR-003) | `identity` |
| `search` | `GET /search`, `GET /search/autocomplete` (FR-004) | `identity` |

## Rate Limit Counter (Redis)

The runtime state a Policy check reads/writes. One Redis key per `(policy, key_dimension value)` pair, holding an integer count with a TTL equal to the policy's `window_seconds` (fixed-window counter, mirroring `chat_service.py::RateLimitService`'s existing daily-quota counter shape).

- **Key shape**: `ratelimit:{policy_name}:{origin_or_identity}` (namespaced separately from the existing `rate:user:*`/`rate:guest:*` daily-quota keys chat.py already owns, so the two mechanisms never collide even though both live in the same Redis DB).
- **Value**: integer count, incremented per request.
- **TTL**: set on first increment to `window_seconds`; expires and resets automatically (no cleanup job needed).

## Rate Limit Refusal

Not a stored entity — the shape of the error raised/returned when a Policy's counter exceeds `max_requests` (research.md Decision 3).

| Field | Type | Notes |
|---|---|---|
| `code` | string | `RATE_LIMIT_EXCEEDED`, added to the existing `_CATEGORY_MAPPING` in `backend/exceptions/handlers.py`. |
| `message` | string | User-facing, non-sensitive (which limit, not why it's set at that value). |
| `retry_after_seconds` | int | How long until the caller's window resets; derived from the counter's Redis TTL at refusal time. |
| `request_id` | string | Already part of the shared `ErrorResponse`/`ErrorBody` contract — no change needed here, just inherited. |

Carried on the `RateLimitExceededError(DomainError)` exception and surfaced through the existing `ErrorResponse` JSON body (same shape as every other mapped `DomainError`), status `429`.

## API Contract (export artifact)

The backend's OpenAPI schema, exported to a static file (research.md Decision 6).

| Field | Type | Notes |
|---|---|---|
| File path | — | A single checked-in JSON file (e.g. `backend/openapi.json`), regenerated by `scripts/export_openapi_schema.py`. |
| Source | — | `app.openapi()` from the live FastAPI `app` object — always reflects current router `response_model`/request-body Pydantic models, nothing hand-maintained. |
| Coverage gap report | — | A companion file/log entry (research.md Decision 9) listing endpoints whose request or response isn't backed by a Pydantic schema (raw `dict` bodies, missing `response_model`) — informational, not a build failure. |

## Generated Frontend Type Definitions (build artifact)

| Field | Type | Notes |
|---|---|---|
| File path | — | A single checked-in generated file under `frontend/lib/api/` (e.g. `frontend/lib/api/generated-types.ts`), produced from the API Contract file by the chosen types-only generator (research.md Decision 7). |
| Regeneration | — | Deterministic given an unchanged API Contract file (FR-010); no manual edits ever made to this file (enforced by convention + the CI drift check, research.md Decision 8). |
| Consumers | — | The existing per-domain files in `frontend/lib/api/*.ts` (e.g. `topics.ts`, `articles.ts`) import types from here instead of declaring their own `interface` (FR-011); their fetch functions and `apiFetch` usage are unchanged. |
